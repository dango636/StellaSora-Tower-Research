# 星塔爬塔：状态空间描述

## 0. 模型设置

本文完整规定：计分、预设、楼层顺序、可见状态、隐藏状态、观察更新、全部动作、潜能抽取、强化、商店、收入、NPC 及事件。

各项中间结论、当前工作模型依据与长期观察目标见 [状态空间观察清单](StateSpace_Observation_Targets.md)。游戏硬规则不进入验证清单；实测支持的中间结论仅在出现可靠反例时重新审查。

完整带音符对局的扩展见[音符状态空间](NoteStateSpace.md)及[音符观察报告](NoteStateSpace_Observation_Targets.md)。

当前模型版本：`state_space_e6_l49_npc_event_v3`。采用拟合较好的工作假设：一级门统一49/100、商店E6联合核、第3层NPC事件奖励回调旗标。以下公式直接用于模拟与学习；验证状态和竞争假说保留在观察清单中，统计支持不等于游戏硬规则。

### 0.2 游戏状态与玩家知道的状态

1. **游戏状态**：实际持有、金币、当前页面、隐含计数等。
2. **玩家知道的状态**：公开状态加隐藏计数的后验分布。决策只能基于这个状态。

已知初始有序目录且采用本文交换算法时，可由完整历史推导当前池序。普通品质部分页通常不能识别初序；未知初序保留相容配置，不给所有排列擅自赋先验。

## 1. 计分、目标与预设

令每项非核心潜能 i 的预设目标为 t_i∈{0,…,6}，实际等级为 l_i∈{0,…,6}，未学时 l_i=0。

\[
U(s)=\sum_i\min(t_i,l_i),\qquad
Z(s)=U(s)+6,\qquad
C_{\max}=\sum_i t_i.
\]

U 是普通有效等级，Z 是含核心总有效等级。不是“已有潜能种数”，也不是“实际等级总和”。

例如目标 3、实际 5，只计 3；目标 0、实际 5，计 0，但该项仍影响角色已学种数、旧潜能候选、强化候选以及后续抽取。预设不会缩小游戏中的合法潜能池。

给定同一固定策略 π：

\[
p_T(s)=P_\pi(Z_{\rm end}\ge T\mid s)
      =P_\pi(U_{\rm end}\ge T-6\mid s).
\]

终局前当前 U 只会不减；终局总分在 [U+6,C_max+6]。金币不在终局计分，剩余金币没有残值。

### 1.1 任意预设的输入

每角色输入其全部合法非核心潜能 ID、品质、目标等级，包含目标为 0 的项，并提供按角色×身份×品质区分的完整有序目录 catalogueOrder。初始池使用该目录顺序，不统一按真实 ID 升序；未知顺序保留相容配置。分为六个有序列表：

1. 主角稀有；
2. 主角普通品质；
3. 援护 1 稀有；
4. 援护 1 普通品质；
5. 援护 2 稀有；
6. 援护 2 普通品质。

本项目研究的每角色池为 3 稀有＋9 普通品质，共 12 项。转移公式在抽象上可用于其他长度的合法池。未知角色的合法 ID、品质及游戏是否仍使用同一规则必须由输入目录提供，不能从目标名字猜测或仅输入目标项。

混合预设，例如 6666333＋666666＋666631，是每项 t_i 不同；转移概率不因此改变。记录实际等级 l_i，而不是把达到目标当成游戏满级。

node 指向“下一条尚未处理的指令”，从 1 开始。处理一条时先将 node 加 1；由该指令打开的页面结束后，继续新的 node。floor 是最近处理指令的层数，不能代替 node。

## 3. 状态空间：完整字段定义

### 3.1 公开状态与可由完整历史恢复的状态

| 字段 | 类型／取值 | 含义与更新 |
|---|---|---|
| modelVersion | 字符串 | 冻结规则版本 |
| presetId／catalogue | ID、品质、目标清单 | 包含所有合法非核心项；整局固定 |
| cap | 非负整数 | 所有目标等级之和 |
| phase | 枚举，见下表 | 当前所在流程步骤 |
| node | 1～46 | 下一条未处理路线指令 |
| floor | 0～20 | 当前层数 |
| H | 稀疏行表 | [role,quality,target,actual,count] |
| pools | 六个有序向量 | 尚未学习潜能的目标标签，顺序必须保留 |
| P | 布尔 | 最近展示的新潜能是否为 1 级 |
| Q | 布尔 | 最近一项非 1 级新潜能是否为 2 级；h=10 后规范化为 false |
| h | 0～10 | 实际确认取得的新 3 级潜能次数 |
| coins | 非负整数 | 当前已观察金币 |
| freeEnhance | 布尔 | 本局免费强化是否还可用 |
| paidIndex | 0～6 | 当前机器下一次付费强化档，6 表示 740 封顶档 |
| stock | 2×3 非负整数 | 行为普通特饮／主角特饮，列为 100／160／200 金币 |
| restocks | 0～2 | 本局剩余补货次数 |
| firstInitial | 布尔 | 尚未观察的货架是否为首家初始货架 |
| npc3EventReward | 布尔 | 首核心至第一自然奖励前是否创建事件专用潜能奖励；第3层检查后清除 |
| shopOrdinal | 0～4 | 当前／最近一家商店序号 |
| shopReturnPhase | 阶段 | 当前商店离开后返回 ADVANCE；可为 END |
| offer | 候选行表 | [isNew,role,quality,target,oldLevel,newLevel,poolIndex] |
| source | 奖励来源结构或空 | 见 3.3 |
| seen | 事件类型集合 | 出现即加入；直接关闭不移除 |
| k | 0～4 | 上一次追加 NPC 后累计战斗数，截到 4 |
| A | 布尔 | 第 1 层是否出现追加 NPC；第 3 层检查结束后清零 |
| eventId | 0 或 101～128 | 当前事件；0 表示没有事件 |
| eventOptions | 静态选项 ID 集合 | 当前显示、可执行、按目标投影后保留的选项，含关闭 0 |

H 的 quality=1 为稀有，quality=2 为普通品质；role=1 为主角，2、3 为援护。actual 只能为 1～6，未学项目不能以 actual=0 放入 H。每个类别 count 是该类别不同潜能 ID 的个数，不是等级。H 可以按四个类别字段排序以规范化。

如果两个已学潜能的角色、品质、目标、实际等级完全相同，未来转移只需知道数量，允许合并。不同未学潜能即使目标相同，也必须保留池位置。

### 3.2 阶段和动作

| phase | 意义 | 可采取的动作 |
|---|---|---|
| ADVANCE | 处理自动路线至下个可观察界面 | ADVANCE，强制 |
| CORE | 核心确认观察点 | CONFIRM_CORE，强制；核心无需动态优化 |
| DRAW | 已取得一次普通奖励，尚未生成候选 | GENERATE_PAGE，强制 |
| PAGE | 普通潜能候选已经展示 | SELECT；满足条件时 REROLL |
| ENHANCE_PAGE | 强化候选已经展示 | SELECT，不提供普通页重抽 |
| EVENT_DRAW | 已确定 NPC 出现，尚未生成类型 | GENERATE_EVENT，强制 |
| EVENT | 已显示完整事件菜单 | 可执行 EVENT_OPTION；SKIP_EVENT |
| SHOP_UNSEEN | 商店货架尚未观察 | OPEN_SHOP，强制免费观察 |
| SHOP | 货架已经观察 | BUY、ENHANCE、RESTOCK、LEAVE |
| END | 最终商店结束 | 无动作，返回终分 |

DRAW／EVENT_DRAW 等是内部计算阶段，并不表示要求软件额外点击一次。UI 已经展示的真实候选必须直接作为 PAGE／ENHANCE_PAGE 输入，不能再调用生成器随机生成一次。

打开、关闭商店面板去操作强化是免费 UI 行为，不改变商品。模型把这些操作折叠为同一 SHOP。LEAVE 专指离开当前商店房间，不是关闭货架面板。

### 3.3 奖励来源结构

~~~json
{
  "roleMode": "any",
  "boundRole": 0,
  "rarity": "regular",
  "returnPhase": "ADVANCE",
  "rerollAllowed": true
}
~~~

| 字段 | 可用值 |
|---|---|
| roleMode | any：三个角色按权重；main：仅主角；bound：指定 role |
| boundRole | roleMode=bound 时为 1／2／3；其他为 0 |
| rarity | regular：稀有基础 1/5；common：0；rare：1 |
| returnPhase | 完成候选确认后的返回阶段，通常 ADVANCE 或 SHOP |
| rerollAllowed | 当前界面是否允许重抽；普通奖励默认 true，强化 false |

援护随机奖励创建时先以 1/2、1/2 绑定援护 2 或 3，再生成页面；本次奖励的所有重抽保持该绑定。any 来源重抽会重新按当时持有数量选角色。费用在奖励创建前扣一次，重抽只再扣 40。

### 3.4 真正的隐藏状态

| 隐藏字段 | 取值 | 含义 |
|---|---|---|
| gE | 0～5 | 本局后台强化 +2 已触发次数 |
| fE | 0～3 | 自上次 +2 后连续没触发次数 |
| gC | 0～5 | 本局额外 +50 已触发次数 |
| fC | 0～3 | 自上次 +50 后连续没触发次数 |
| G1 | 0／1 | 首战是否额外 +50；第 3 层特殊 NPC 概率使用，之后清零 |

达到成功上限时规范化为 (g=5,f=0)。不同隐藏计数可产生完全相同的界面：典型是所有强化候选均为 5→6，或两场自动战斗只看到合计 +50。

策略状态保存：

- eBel：[(gE,fE,精确概率),…]；
- cBel：[(gC,fC,G1,精确概率),…]。

概率非负，重复坐标合并，零概率删除，精确总和为 1，按坐标排序。

完整本局日志、独立初始计数和本冻结核下，可以分别维护上述两个后验：金币相关观察不读取强化计数，强化观察不读取金币计数，已知动作只按观察实施。若由缺失历史产生了额外相关性，必须改存**联合后验**；不得未经证明把联合分布拆成两个边缘。

忽略不可达组合，强化原始计数最多 6×4=24 格；金币加 G1 最多 48 格，联合上界 1,152 格。规范化后更少。

观测字段分别判断有效性：ID、角色、品质、新旧、旧等级、显示等级和确认不互相替代。unknown不遮蔽独立可读的UI字段；已标无效的字段不回退原始OCR重用。等级统计可使用独立有效的等级字段，库存及ID推导仍要求相应字段完整。

### 3.5 不属于策略可见信息的内容

真实抽样的 gE/fE/gC/fC、未来随机种子、尚未展示的候选、尚未打开的折扣、各场未单独观察的 +50、尚未执行的赌博结果，均不得用于选动作。

如果历史完整，部分洗牌前的 ID 池及这一页按顺序显示的新 ID，可唯一恢复每一步交换及完整后池。因此它可以进入公开摘要。若只有“目标／非目标”标签，没有真实 ID 历史，不能反推交换位置；这时需要池顺序的后验，而不是任取一条序列。

## 5. 普通潜能页生成：精确随机链

本节统一用于自然奖励、商店饮料和事件潜能。一次正常普通奖励生成 3 个不同候选。

### 5.1 选择角色

c_r 为角色 r 实际已经学会的非核心潜能种数，包含目标为 0 和已满 6 级的项：

\[
c_r=\sum_{H:\,role=r} count,\quad
\tau_r=\begin{cases}6&r=1\\5&r=2,3\end{cases}
\]

\[
d_r=\min(4,\max(0,\tau_r-c_r)),\quad
w_r=\max(1,\min(100,30d_r-10)).
\]

any 来源用权重 (4w_1,3w_2,3w_3) 归一化选一个角色。main 与 bound 直接按限制选。

| 已学种数 | 主角权重 | 每名援护权重 |
|---:|---:|---:|
| 0～1 | 400 | 300 |
| 2 | 400 | 240 |
| 3 | 320 | 150 |
| 4 | 200 | 60 |
| 5 | 80 | 3 |
| ≥6 | 4 | 3 |

### 5.2 决定已有候选数

选定角色后，c 是已学种数，u 是其中实际 1～5 级的种数。基础概率：

\[
q(c,r)=
\begin{cases}
0&c\le1\\
51/100&2\le c\le3\\
3/4&4\le c<\tau_r\\
1&c\ge\tau_r.
\end{cases}
\]

先抽 J∼Binomial(3,q)，再取已有候选数 o=min(J,u)，新候选数 n=3−o。把被截到同一个 o 的概率相加。不能改成“每个已学潜能独立以 q 出现”。

已有不足时补为新；新总库存也不足的分支属于第 13 节的未覆盖边界，不私自跨新旧补齐。

### 5.3 分别生成新与已有的品质数量

来源稀有基础概率 p_R 为 regular=1/5、common=0、rare=1。

对新与已有两个部分**独立**执行：

- 该部分需抽 k 项，合法稀有库存 R、普通库存 C。
- 若 k>R+C，返回 MODEL_GAP。
- 抽 B∼Binomial(k,p_R)。
- 稀有数量 r=min(min(k,R), max(max(0,k−C),B))。
- 普通数量 k−r。

这是品质库存裁剪；只在同一“新／已有”部分内回填另一品质，不能拿新替已有或反过来。稀有来源不是保证最终三个都是稀有，库存不足仍有回填。

### 5.4 已有候选：等概率不放回

每个角色／品质的已有未满 ID 等概率，不放回选对应数量，普通升级显示 newLevel=oldLevel+1。

压缩 H 时，同类别抽取向量 x 的概率为：

\[
P(x)=\frac{\prod_j{m_j\choose x_j}}{{\sum_jm_j\choose k}},
\quad \sum_jx_j=k,\quad 0\le x_j\le m_j.
\]

不要在“类别”之间等概率抽，类别有几个实际 ID 必须作为权重。已有候选不改变 P/Q/h。

### 5.5 新候选：保留顺序的部分交换

对对应有序池 A，长度 M，需要取 k：

~~~text
if k == 0:
    原池不变，无候选
else if k == M:
    原池不变，候选就是当前整池顺序
else:
    for j = 1..k:
        v = UniformInteger(j,M)
        swap(A[j],A[v])
    候选 = A[1..k]
    持久保存整个交换后的 A
~~~

全池取出分支不再洗牌。这一点决定不同池顺序可能有不同未来价值。不得把池排序或只记录各目标数量。

显示后未选的候选仍在池中；重抽不会恢复旧顺序。确认新潜能时，以当前池末项覆盖所选位置，再删除末项。

### 5.6 新潜能显示等级

依次处理本页**新稀有 → 新普通品质**，每部分按抽出顺序。整页使用进入时的同一个 h；同页不会因展示 3 级而增加 h。

对每一个新候选：

~~~text
p1 = 49/100
if P == false and Bernoulli(p1) == true:
    level = 1
    P = true
    Q 保持不变
else:
    if h == 10:
        level = 2
        P = false
        Q = false
    else if Q == true:
        level = 3
        P = false
        Q = false
    else:
        level = 2，概率 1/3；或 level = 3，概率 2/3
        P = false
        Q = (level == 2)
~~~

当 P=true 时，不执行一级概率判断，直接进入非一级部分。P=false 时一级概率统一为49/100。h=10 时非一级固定二级，Q 已无作用，统一存 false；P 仍有效。因此 h=10、P=false 时一级/二级概率为49/100、51/100；P=true 时必为二级。

**展示即更新 P/Q，确认才更新 h。** 这一规则包括没有选择和后来被重抽掉的新候选。旧候选、强化和核心都不进入该历史。

### 5.7 页面的公开结果

生成后的状态进入 PAGE，包含：

- 角色和三个具体候选；
- 每个候选的新旧、品质、目标、旧等级、显示等级、对应池位置；
- 交换后的完整六池；
- 展示后的 P/Q；
- 未改变的 H、h、金币和来源。

同一实际可见结果的随机路径必须先合并。

## 6. 普通页确认与重抽

### 6.1 SELECT

新候选：

1. 从本页后池按 poolIndex 执行末项覆盖删除。
2. 将该 ID 按显示等级加入 H。
3. 若显示等级是 3，则 h 增加 1；达到 10 时 Q=false。
4. 返回 source.returnPhase，清空 offer 和 source。

已有候选：

1. H 中所选 ID／类别的旧等级减少一项；
2. 在显示的新等级增加一项；
3. P/Q/h 不再更新；
4. 返回指定阶段并清空页面。

确认不重复付奖励原始费用，不重新生成概率。

### 6.2 REROLL

仅在 PAGE、界面允许且 coins≥40 时：

- 扣 40；
- H 与 h 不变；
- 保留当前后池和已经推进的 P/Q；
- 保留 source，包括绑定角色、品质及返回阶段；
- 清空 offer，进入 DRAW；
- 按完整普通生成链生成新页面。

无限次重抽是指没有独立次数上限，仍受有限金币约束。没有“付费重抽后必须接受”之类额外限制。

## 7. 强化机器

### 7.1 候选与共享增量

从全队所有实际 1～5 级非核心潜能 ID 中，均匀不放回选择 min(3,M) 个。所有候选共享同一次后台增量 δ∈{1,2}，显示 min(6,l+δ)。目标为 0 的项照常参与。

后台 +2 概率：

\[
b_E(g,f)=
\begin{cases}
0&g=5\\
\min(3(f+1),10)/10&g<5.
\end{cases}
\]

即 3/10、3/5、9/10、1。触发后 (g,f)→(g+1,0)；不触发后 (g,f)→(g,min(f+1,3))；g 达到 5 后规范化为 (5,0)。

### 7.2 所有候选 5→6 时

δ=1 和 δ=2 显示相同，但 δ=2 仍消耗一次成功次数。必须按观测做贝叶斯更新，把两种后台路径留在 eBel 中。

例：此前确定 (gE,fE)=(0,0)，本次全 5→6。展示后后验为：

- 3/10 在 (1,0)；
- 7/10 在 (0,1)。

下一次 +2 概率是 3/10×3/10＋7/10×3/5=51/100。不能把这次当成确定失败，也不能沿抽样真值直接给玩家下一次策略。

若候选中至少有一个旧等级≤4，显示可区分 δ=1 与 2，按对应似然条件化后验。候选 ID 子集的均匀概率与 δ 独立。

### 7.3 费用与更新时机

本局第一次强化免费；freeEnhance=true 时扣 0 并改为 false，不推进 paidIndex。

付费序列：

| paidIndex，0 基 | 0 | 1 | 2 | 3 | 4 | 5 | 6 及以后 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 费用 | 60 | 120 | 180 | 260 | 340 | 540 | 740 |

付费后 paidIndex=min(6,paidIndex+1)。进入新商店时 paidIndex=0；免费次数和 eBel 不重置。补货不重置任何强化进度。

只有 M>0 且支付得起时才能 ENHANCE。支付、隐藏计数转移与候选展示在同一次强化请求中完成；确认只更新所选潜能。强化页没有 40 金币重抽。

## 8. 商店与货架

### 8.1 数量生成

八件商品。数量采用E6联合工作核。令 `b=int(shopOrdinal==1)`，首店初始货架及首店补货均取1，其余取0。每个新货架重置编号0～9的十张票，仅为Y/B不放回抽两张；X另行生成：

~~~text
u, v = sample_without_replacement(range(10), 2)
Y = int(u < 6)
B = int(v < 8)
X = min(2, Binomial(4, 0.65 - 0.05*Y))
G = 2 - b + X
M = b + Y
small = 6 - X - Y - B
~~~

G是普通特饮数，M是主角特饮数，B为大音符包数，small为小音符包数。Y是扣除首店保底后的额外主饮，不等于M。给定Y后X与B独立；Y/B联合概率如下，不能将三者独立拼接。

| (Y,B) | (0,0) | (0,1) | (1,0) | (1,1) |
|---|---:|---:|---:|---:|
| 概率 | 1/15 | 5/15 | 2/15 | 7/15 |

Y边际为3/5，B边际为4/5。大／小音符可合并为8−G−M个非饮料占位；不能删掉占位后只在饮料中分折扣。十票仅在当前架的Y/B间共享，不跨货架，也不生成X的四次机会。

### 8.2 折扣生成

先在全部八件中均匀选择四件为折扣商品。第2、3家商店的**初始货架**使用 p_D=3/4；第1、4家商店初始货架以及全部商店的任何补货使用 p_D=7/10。五折件数：

\[
D=\min(2,\operatorname{Binomial}(3,p_D)).
\]

| 适用货架 | D=0 | D=1 | D=2 |
|---|---:|---:|---:|
| 第2、3家初始货架（p_D=3/4） | 1/64 | 9/64 | 54/64 |
| 第1、4家初始货架及全部补货（p_D=7/10） | 27/1000 | 189/1000 | 784/1000 |

D 独立抽取，不复用§8.1的饮料数量随机量 X。初始货架与补货由商店序号和当前操作区分。

在四件折扣商品中均匀选择 D 件五折，其余四件中的 4−D 件八折；非折扣四件原价。饮料原价 200，因此价格只可能 100、160、200。每个折扣子集的条件概率分别为 1/C(8,4) 和 1/C(4,D)。

生成完整货架后，边际化为 stock[普通／主角][100／160／200]。真实页面按类型、价格及商品 ID 排列，显示顺序不表示后台生成次序。

### 8.3 行动顺序

先 OPEN_SHOP 免费看到折扣，才选后续动作。候选行为：

- BUY：购买一种当前饮料，扣价、移除一瓶，进入对应 DRAW；完成潜能选择后返回原 SHOP。
- ENHANCE：扣当前机器费用并展示强化；确认后返回原 SHOP。
- RESTOCK：支付 100，restocks 减 1，整架替换；数量仍取 `b=int(shopOrdinal==1)`，折扣使用补货分布。
- LEAVE：结束当前商店，推进路线；最终一家结束后才 END。

可买后强化、强化后买、交替、多次补货；购买或强化生成的当前奖励必须先处理完，不能带着未选页面继续买下一瓶。

## 9. 战斗金币与追加 NPC

### 9.1 额外金币

每场战斗先加对应基础金币，再用：

\[
b_C(g,f)=
\begin{cases}
0&g=5\\
\min(30(f+1),100)/101&g<5
\end{cases}
\]

判断是否额外加 50。四档为 30/101、60/101、90/101、100/101，不是 30%、60%、90%、100%。

成功后 (g,f)→(g+1,0)；失败后 f 截到 3；达到五次成功后规范化 (5,0)。第 1 场额外金币同时写入 G1，第 3 层特殊检查后 G1 清零。

第 7 层照常结算。不同战斗的随机判断依赖计数；不可以把每场都写成独立固定 30%。

### 9.2 金币观察边界

自动推进到下一处实际界面时，才用可见金币更新 cBel。冻结采集模型中：

- 第 7、8 层之间没有一个可决策且单独记录金币的界面，观察到的是两场合计；
- 第 14 层若没有追加 NPC，会与第 15 层一起到下一个核心界面；
- 第 14 层若出现 NPC，则其事件界面提供中间金币观察；
- 核心虽不优化，仍保留为金币观察点。

因此相同合计金币可能来自多个后台路径。例如两场中恰有一次 +50 时，不能自行认定发生在前一场或后一场。

### 9.3 追加 NPC 次数

每场战斗令 k=min(4,k+1)，包含第 7 层。只在第 1、3、10、14、17 层检查追加 NPC。

除第 3 层外：

\[
P(\text{追加 NPC})=\min(30k,100)/101.
\]

出现后 k=0；未出现不归零。固定事件、商店、关闭 NPC 都不额外改变 k；关闭前该次追加已算出现并归零。

第 3 层：

\[
P(\text{追加 NPC at 3})=(50-30A+30G1(1-\mathbf1[\mathrm{npc3EventReward}]))/101.
\]

A表示第1层是否出现追加NPC。npc3EventReward初始为false，仅首核心至第一自然奖励前创建事件专用潜能奖励时置true；普通自然奖励、核心奖励及纯金币事件不置位。实际G1始终保留首战是否额外+50的含义，不因该回调修改。令有效标志 `G1eff=G1*(1-int(npc3EventReward))`，四种概率：

| A | G1eff | 第 3 层概率 |
|---:|---:|---:|
| 0 | 0 | 50/101 |
| 0 | 1 | 80/101 |
| 1 | 0 | 20/101 |
| 1 | 1 | 50/101 |

第1层检查写入A；第3层检查结束后A、G1均清零，npc3EventReward恢复false，仍按第3层是否出现更新k。先使用有效标志计算概率，再清除。npc3EventReward来自公开奖励创建历史，不扩充cBel的隐藏坐标。

### 10.4 事件后状态

## 11. 观察合并与后验更新

记 x 为公开状态，z 为隐藏状态，b(z) 为后验。动作 a 的微观核给出 (x',z',o)。必须先计算：

\[
P(o\mid x,b,a)=\sum_{z,z'}b(z)P(x',z',o\mid x,z,a)
\]

\[
b_o(z')=
\frac{\sum_z b(z)P(x',z',o\mid x,z,a)}
     {P(o\mid x,b,a)}.
\]

相同 o 对应的 x' 必须相同，或能从 o 与已知历史唯一恢复。策略后继是 (x',b_o)，不是每条 z' 微观路径。

只用“当前 +2 概率”替代 eBel 不够：确定 (0,0)，与 3/10 在 (0,3) 加 7/10 在 (5,0)，当前成功率同为 3/10；观察下一次失败后，前者再下一次为 3/5，后者为 0。

## 12. 有限时域的资源上界

从本文标准开局出发，最多出现 3 个固定事件＋5 个追加事件，共 8 个；每类去重。所有事件中可产生的最高正金币增量，取最大的八项为 650、150、120、120、100、100、100、30，合计 1,370。因此整局可获得的金币总额不超过 400＋4,180＋250＋1,370＝**6,200**，所有支出只会减少它。

最小正金币操作成本为 40，所以付费操作至多 155 次。把每次付费动作都宽松地算成“动作＋一次潜能确认”，另加 13 次自然确认、至多 8 次事件潜能确认、一次免费强化及确认、至多 8 个事件选择、4 次离店与一次起始自动推进，折叠自动流程后的决策步数上界为 **346**。
