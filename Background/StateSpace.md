### 0.2 游戏状态与玩家知道的状态

1. **游戏状态**：实际持有、金币、当前页面、隐含计数等。
2. **玩家知道的状态**：公开状态加隐藏计数的后验分布。决策只能基于这个状态。

## 1. 计分、目标与预设

令每项非核心潜能 i 的预设目标为 t_i∈{0,…,6}，实际等级为 l_i∈{0,…,6}，未学时 l_i=0。

\[
U(s)=\sum_i\min(t_i,l_i),\qquad
Z(s)=U(s)+6,\qquad
C_{\max}=\sum_i t_i.
\]

U 是普通有效等级，Z 是含核心总有效等级。不是“已有潜能种数”，也不是“实际等级总和”。

例如目标 3、实际 5，只计 3；目标 0、实际 5，计 0，但该项仍影响角色已学种数、旧潜能候选、强化候选以及后续抽取。预设不会缩小游戏中的合法潜能池。

给定同一固定策略 π：

\[
p_T(s)=P_\pi(Z_{\rm end}\ge T\mid s)
      =P_\pi(U_{\rm end}\ge T-6\mid s).
\]

终局前当前 U 只会不减；终局总分在 [U+6,C_max+6]。金币不在终局计分，剩余金币没有残值。

### 1.1 任意预设的输入

每角色输入其全部合法非核心潜能 ID、品质、目标等级，包含目标为 0 的项，并提供按角色×身份×品质区分的完整有序目录 catalogueOrder。初始池使用该目录顺序，不统一按真实 ID 升序；未知顺序保留相容配置。分为六个有序列表：

1. 主角稀有；
2. 主角普通品质；
3. 援护 1 稀有；
4. 援护 1 普通品质；
5. 援护 2 稀有；
6. 援护 2 普通品质。

本规格的每角色池为3稀有＋9普通品质，共12项。合法ID、品质及初序由完整输入目录给出；缺少目录或目录不符合本规格时，返回MODEL_GAP(CATALOGUE_MISSING_OR_UNSUPPORTED)。

客户端`CharPotential`数组可确定合法目录和预选码位序，但没有已恢复的生成链证明该位序就是服务端随机池初序。角色列表与图鉴还会另行排序，因此不能用静态数组或UI排序替代这里要求的真实初序；U02继续保留。

混合预设，例如 6666333＋666666＋666631，是每项 t_i 不同；转移概率不因此改变。记录实际等级 l_i，而不是把达到目标当成游戏满级。

## 3. 状态空间：完整字段定义

### 3.1 公开状态与可由完整历史恢复的状态

| 字段 | 类型／取值 | 含义与更新 |
|---|---|---|
| modelVersion | 字符串 | 冻结规则版本 |
| presetId／catalogue | ID、品质、目标清单 | 包含所有合法非核心项；整局固定 |
| cap | 非负整数 | 所有目标等级之和 |
| phase | 枚举，见下表 | 当前所在流程步骤 |
| node | 1～46 | 下一条未处理路线指令 |
| floor | 0～20 | 当前层数 |
| H | 稀疏行表 | [role,quality,target,actual,count] |
| pools | 六个有序向量 | 尚未学习潜能的目标标签，顺序必须保留 |
| P | 布尔 | 最近展示的新潜能是否为 1 级 |
| Q | 布尔 | 最近一项非 1 级新潜能是否为 2 级；h=10 后规范化为 false |
| h | 0～10 | 实际确认取得的新 3 级潜能次数 |
| coins | 整数 | 当前金币，按实际变化量直接更新，不另夹零 |
| freeEnhance | 布尔 | 本局免费强化是否还可用 |
| paidIndex | 0～6 | 当前机器下一次付费强化档，6 表示 740 封顶档 |
| stock | 2×3 非负整数 | 行为普通特饮／主角特饮，列为 100／160／200 金币 |
| restocks | 0～2 | 本局剩余补货次数 |
| firstInitial | 布尔 | 尚未观察的货架是否为首家初始货架 |
| shopOrdinal | 0～4 | 当前／最近一家商店序号 |
| shopReturnPhase | 阶段 | 当前商店离开后返回 ADVANCE；可为 END |
| offer | 候选行表 | [isNew,role,quality,target,oldLevel,newLevel,poolIndex] |
| source | 奖励来源结构或空 | 见 3.3 |
| seen | 事件类型集合，不含121 | 除121外出现即加入；直接关闭不移除；包含105的出现记忆 |
| k | 0～4 | 上一次追加 NPC 后累计战斗数，截到 4 |
| eventId | 0 或 101～128 | 当前事件；0 表示没有事件 |
| eventOptions | 静态选项 ID 集合 | 当前显示、可执行、按目标投影后保留的选项，含关闭 0 |

H 的 quality=1 为稀有，quality=2 为普通品质；role=1 为主角，2、3 为援护。actual 只能为 1～6，未学项目不能以 actual=0 放入 H。每个类别 count 是该类别不同潜能 ID 的个数，不是等级。H 可以按四个类别字段排序以规范化。

如果两个已学潜能的角色、品质、目标、实际等级完全相同，未来转移只需知道数量，允许合并。不同未学潜能即使目标相同，也必须保留池位置。

### 3.2 阶段和动作

| phase | 意义 | 可采取的动作 |
|---|---|---|
| ADVANCE | 处理自动路线至下个可观察界面 | ADVANCE，强制 |
| CORE | 核心确认观察点 | CONFIRM_CORE，强制；核心无需动态优化 |
| DRAW | 已取得一次普通奖励，尚未生成候选 | GENERATE_PAGE，强制 |
| PAGE | 普通潜能候选已经展示 | SELECT；满足条件时 REROLL |
| ENHANCE_PAGE | 强化候选已经展示 | SELECT，不提供普通页重抽 |
| EVENT_DRAW | 已确定 NPC 出现，尚未生成类型 | GENERATE_EVENT，强制 |
| EVENT | 已显示完整事件菜单 | 可执行 EVENT_OPTION；SKIP_EVENT |
| SHOP_UNSEEN | 商店货架尚未观察 | OPEN_SHOP，强制免费观察 |
| SHOP | 货架已经观察 | BUY、ENHANCE、RESTOCK、LEAVE |
| END | 最终商店结束 | 无动作，返回终分 |

DRAW／EVENT_DRAW 等是内部计算阶段，并不表示要求软件额外点击一次。UI 已经展示的真实候选必须直接作为 PAGE／ENHANCE_PAGE 输入，不能再调用生成器随机生成一次。

打开、关闭商店面板去操作强化是免费 UI 行为，不改变商品。模型把这些操作折叠为同一 SHOP。LEAVE 专指离开当前商店房间，不是关闭货架面板。

### 3.3 奖励来源结构

~~~json
{
  "roleMode": "any",
  "boundRole": 0,
  "rarity": "regular",
  "returnPhase": "ADVANCE",
  "rerollAllowed": true
}
~~~

| 字段 | 可用值 |
|---|---|
| roleMode | any：三个角色按权重；main：仅主角；bound：指定 role |
| boundRole | roleMode=bound 时为 1／2／3；其他为 0 |
| rarity | regular：稀有基础 1/5；common：0；rare：1 |
| returnPhase | 完成候选确认后的返回阶段，通常 ADVANCE 或 SHOP |
| rerollAllowed | 当前界面是否允许重抽；普通奖励为true，强化为false |

援护随机奖励创建时先以 1/2、1/2 绑定援护 2 或 3，再生成页面；本次奖励的所有重抽保持该绑定。any 来源重抽会重新按当时持有数量选角色。费用在奖励创建前扣一次，重抽只再扣 40。

### 3.4 真正的隐藏状态

| 隐藏字段 | 取值 | 含义 |
|---|---|---|
| gE | 0～5 | 本局后台强化 +2 已触发次数 |
| fE | 0～3 | 自上次 +2 后连续没触发次数 |
| gC | 0～5 | 本局额外 +50 已触发次数 |
| fC | 0～3 | 自上次 +50 后连续没触发次数 |

达到成功上限时规范化为 (g=5,f=0)。不同隐藏计数可产生完全相同的界面：典型是所有强化候选均为 5→6，或两场自动战斗只看到合计 +50。

策略状态保存：

- eBel：[(gE,fE,精确概率),…]；
- cBel：[(gC,fC,精确概率),…]。

概率非负，重复坐标合并，零概率删除，精确总和为 1，按坐标排序。

在完整本局日志、独立初始计数和本规格转移核下，分别维护上述两个后验：金币相关观察不读取强化计数，强化观察不读取金币计数，已知动作只按观察实施。若由缺失历史产生了额外相关性，必须改存**联合后验**；联合分布不满足独立条件时不得拆成两个边缘。

忽略不可达组合，强化与金币原始计数各最多6×4=24格，联合上界576格；把g=5统一为(5,0)后，各至多21格，联合至多441格。NPC核不读取首战金币旗标，cBel不保存G1。不同过程是否可拆为边缘仍遵守上一段的联合后验条件。

观测字段分别判断有效性：ID、角色、品质、新旧、旧等级、显示等级和确认不互相替代。unknown不遮蔽独立可读的UI字段；已标无效的字段不回退原始OCR重用。等级、库存及ID分别使用其有效输入字段。

### 3.5 不属于策略可见信息的内容

真实抽样的 gE/fE/gC/fC、未来随机种子、尚未展示的候选、尚未打开的折扣、各场未单独观察的 +50、尚未执行的赌博结果，均不得用于选动作。

如果历史完整，部分洗牌前的 ID 池及这一页按顺序显示的新 ID，可唯一恢复每一步交换及完整后池。因此它可以进入公开摘要。若只有“目标／非目标”标签，没有真实 ID 历史，不能反推交换位置；这时需要池顺序的后验，而不是任取一条序列。

- H 与未学池按角色／品质合计的实际 ID 数保持不变，同一 ID 不能同时存在于二者。
- t∈[0,6]，已学 l∈[1,6]；h∈[0,10]，paidIndex∈[0,6]。
- 新候选的 poolIndex 指向**本页已生成后的池**，且该位置的 ID／目标匹配。
- 普通页所有候选来自同一角色；强化页可以跨三个角色。
- 已显示的非121事件必须在seen；121不加入seen。目录未定义的事件／选项返回MODEL_GAP(EVENT_INPUT_MISSING)。
- 当前金币与已记录交易能闭合；重复读到同页不会再扣款或更新 P/Q/h。
- 快照不能仅由 floor＋coins＋H 构成：同层多个奖励、重抽、商店交替和隐藏计数都会造成不同未来。

## 5. 普通潜能页生成：精确随机链

本节统一用于自然奖励、商店饮料和事件潜能。一次正常普通奖励生成 3 个不同候选。

### 5.1 选择角色

c_r 为角色 r 实际已经学会的非核心潜能种数，包含目标为 0 和已满 6 级的项：

\[
c_r=\sum_{H:\,role=r} count,\quad
\tau_r=\begin{cases}6&r=1\\5&r=2,3\end{cases}
\]

\[
d_r=\min(4,\max(0,\tau_r-c_r)),\quad
w_r=\max(1,\min(100,30d_r-10)).
\]

any 来源用权重 (4w_1,3w_2,3w_3) 归一化选一个角色。main 与 bound 直接按限制选。

| 已学种数 | 主角权重 | 每名援护权重 |
|---:|---:|---:|
| 0～1 | 400 | 300 |
| 2 | 400 | 240 |
| 3 | 320 | 150 |
| 4 | 200 | 60 |
| 5 | 80 | 3 |
| ≥6 | 4 | 3 |

### 5.2 决定已有候选数

选定角色后，c 是已学种数，u 是其中实际 1～5 级的种数。基础概率：

\[
q(c,r)=
\begin{cases}
0&c\le1\\
1/2&2\le c\le3\\
3/4&4\le c<\tau_r\\
1&c\ge\tau_r.
\end{cases}
\]

先抽 J∼Binomial(3,q)，再取已有候选数 o=min(J,u)，新候选数 n=3−o。把被截到同一个 o 的概率相加。不能改成“每个已学潜能独立以 q 出现”。

已有不足时补为新。定义选中角色的满级非核心种数 F=c−u，新总库存 N_new=12−c。在本规格每角色3稀有＋9普通品质的目录和上述q下，存在精确等价关系：

\[
N_{new}<n\quad\Longleftrightarrow\quad F\ge10.
\]

选中角色后，F≥10时返回MODEL_GAP(NEW_POOL_EXHAUSTED)，不生成这一普通页，也不跨新旧改变配额。F≤9时按上述数量核继续。这个判定不受目标等级影响，满级始终指实际6级。

客户端能隐藏短列表的缺失卡槽；空候选时调用callback(1000)，随后向服务端发送Index=999。这只确定空／短响应的本地处理，不证明F≥10时服务端会返回什么或如何结算；U04及上述MODEL_GAP保持。

### 5.3 分别生成新与已有的品质数量

来源稀有基础概率 p_R 为 regular=1/5、common=0、rare=1。

对新与已有两个部分**独立**执行：

- 该部分需抽 k 项，合法稀有库存 R、普通库存 C。
- 若 k>R+C，返回 MODEL_GAP。
- 抽 B∼Binomial(k,p_R)。
- 稀有数量 r=min(min(k,R), max(max(0,k−C),B))。
- 普通数量 k−r。

这是品质库存裁剪；只在同一“新／已有”部分内回填另一品质，不能拿新替已有或反过来。稀有来源不是保证最终三个都是稀有，库存不足仍有回填。

对新分区，令 F_C 为该角色实际已满6级的普通品质ID种数，U_C、U_R分别为实际1～5级的普通、稀有ID种数，C_new=9−F_C−U_C。新普通库存少于分配的新项数的条件为：

\[
C_{new}<n\quad\Longleftrightarrow\quad F_C-U_R\ge7.
\]

该条件成立且F≤9时，新分区总库存仍够用，直接用本节公式把普通库存以外的名额回填为新稀有；F≥10由§5.2返回NEW_POOL_EXHAUSTED。此处的库存判定与来源p_R分别执行，不改动新旧配额。

本节是当前采用的模型核。客户端直接消费服务端最终Infos，没有恢复出新普通库存触边时的品质回填实现，因此U03不因本地目录或展示代码而关闭。

### 5.4 已有候选：等概率不放回

每个角色／品质的已有未满 ID 等概率，不放回选对应数量，普通升级显示 newLevel=oldLevel+1。

压缩 H 时，同类别抽取向量 x 的概率为：

\[
P(x)=\frac{\prod_j{m_j\choose x_j}}{{\sum_jm_j\choose k}},
\quad \sum_jx_j=k,\quad 0\le x_j\le m_j.
\]

不要在“类别”之间等概率抽，类别有几个实际 ID 必须作为权重。已有候选不改变 P/Q/h。

已覆盖小池的均匀规则沿用实测结论。客户端按服务端Infos顺序展示，没有在此链路重新抽样；这不能证明普通已有ID大池的高阶均匀联合分布，U06仍保留。

### 5.5 新候选：保留顺序的部分交换

对对应有序池 A，长度 M，需要取 k：

~~~text
if k == 0:
    原池不变，无候选
else if k == M:
    原池不变，候选就是当前整池顺序
else:
    for j = 1..k:
        v = UniformInteger(j,M)
        swap(A[j],A[v])
    候选 = A[1..k]
    持久保存整个交换后的 A
~~~

全池取出分支不再洗牌。不同池序保留为不同状态，不把池排序或只记录各目标数量。

显示后未选的候选仍在池中；重抽不会恢复旧顺序。确认新潜能时，以当前池末项覆盖所选位置，再删除末项。

### 5.6 新潜能显示等级

依次处理本页**新稀有 → 新普通品质**，每部分按抽出顺序。整页使用进入时的同一个 h；同页不会因展示 3 级而增加 h。

对每一个新候选：

~~~text
p1 = 49/100
if P == false and Bernoulli(p1) == true:
    level = 1
    P = true
    Q 保持不变
else:
    if h == 10:
        level = 2
        P = false
        Q = false
    else if Q == true:
        level = 3
        P = false
        Q = false
    else:
        level = 2，概率 1/3；或 level = 3，概率 2/3
        P = false
        Q = (level == 2)
~~~

当 P=true 时，不执行一级概率判断，直接进入非一级部分。P=false 时一级概率统一为49/100。h=10 时非一级固定二级，Q 已无作用，统一存 false；P 仍有效。因此 h=10、P=false 时一级/二级概率为49/100、51/100；P=true 时必为二级。

**展示即更新 P/Q，确认才更新 h。** 这一规则包括没有选择和后来被重抽掉的新候选。旧候选、强化和核心都不进入该历史。

### 5.7 页面的公开结果

生成后的状态进入 PAGE，包含：

- 角色和三个具体候选；
- 每个候选的新旧、品质、目标、旧等级、显示等级、对应池位置；
- 交换后的完整六池；
- 展示后的 P/Q；
- 未改变的 H、h、金币和来源。

同一实际可见结果的随机路径必须先合并。

## 6. 普通页确认与重抽

### 6.1 SELECT

新候选：

1. 从本页后池按 poolIndex 执行末项覆盖删除。
2. 将该 ID 按显示等级加入 H。
3. 若显示等级是 3，则 h 增加 1；达到 10 时 Q=false。
4. 返回 source.returnPhase，清空 offer 和 source。

已有候选：

1. H 中所选 ID／类别的旧等级减少一项；
2. 在显示的新等级增加一项；
3. P/Q/h 不再更新；
4. 返回指定阶段并清空页面。

确认不重复付奖励原始费用，不重新生成概率。

### 6.2 REROLL

仅在 PAGE、界面允许且 coins≥40 时：

- 扣 40；
- H 与 h 不变；
- 保留当前后池和已经推进的 P/Q；
- 保留 source，包括绑定角色、品质及返回阶段；
- 清空 offer，进入 DRAW；
- 按完整普通生成链生成新页面。

无限次重抽是指没有独立次数上限，仍受有限金币约束。没有“付费重抽后必须接受”之类额外限制。

## 7. 强化机器

### 7.1 候选与共享增量

从全队所有实际 1～5 级非核心潜能 ID 中，均匀不放回选择 min(3,M) 个。所有候选共享同一次后台增量 δ∈{1,2}，显示 min(6,l+δ)。目标为 0 的项照常参与。

后台 +2 概率：

\[
b_E(g,f)=
\begin{cases}
0&g=5\\
\min(3(f+1),10)/10&g<5.
\end{cases}
\]

即 3/10、3/5、9/10、1。令A为全队实际1～5级非核心ID集合，M=|A|>0，k=min(3,M)，p=b_E(g,f)。候选子集S和后台增量δ的联合核为：

\[
P(S,\delta\mid A,g,f)=
\frac{P(\delta\mid g,f)}{\binom{M}{k}},
\qquad S\subseteq A,\ |S|=k,
\]
\[
P(\delta=2\mid g,f)=p,\qquad P(\delta=1\mid g,f)=1-p.
\]

其他子集或增量的联合概率为0。子集不读取δ，增量不读取子集的身份、角色、品质或等级组成；实际显示再逐项应用min(6,l+δ)。触发后 (g,f)→(g+1,0)；不触发后 (g,f)→(g,min(f+1,3))；g 达到 5 后规范化为 (5,0)。

### 7.2 所有候选 5→6 时

δ=1 和 δ=2 显示相同，但 δ=2 仍消耗一次成功次数。必须按观测做贝叶斯更新，把两种后台路径留在 eBel 中。

例：此前确定 (gE,fE)=(0,0)，本次全 5→6。展示后后验为：

- 3/10 在 (1,0)；
- 7/10 在 (0,1)。

下一次 +2 概率是 3/10×3/10＋7/10×3/5=51/100。不能把这次当成确定失败，也不能沿抽样真值直接给玩家下一次策略。

若候选中至少有一个旧等级≤4，显示可区分 δ=1 与 2，按对应似然条件化后验。候选 ID 子集的均匀概率与 δ 独立。

### 7.3 费用与更新时机

本局第一次强化免费；freeEnhance=true 时扣 0 并改为 false，不推进 paidIndex。

付费序列：

| paidIndex，0 基 | 0 | 1 | 2 | 3 | 4 | 5 | 6 及以后 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 费用 | 60 | 120 | 180 | 260 | 340 | 540 | 740 |

付费后 paidIndex=min(6,paidIndex+1)。进入新商店时 paidIndex=0；免费次数和 eBel 不重置。补货不重置任何强化进度。

只有 M>0 且支付得起时才能 ENHANCE。支付、隐藏计数转移与候选展示在同一次强化请求中完成；确认只更新所选潜能。强化页没有 40 金币重抽。

## 8. 商店与货架

### 8.1 数量生成

每架八件商品。令 `b=int(shopOrdinal==1)`，首店初始货架及首店补货均取1，其余取0。按以下顺序生成数量：

~~~text
Y ~ Bernoulli(3/5)
B ~ Bernoulli(5/6 if Y == 0 else 7/9)
X = min(2, Binomial(4, 0.65 - 0.05*Y))
G = 2 - b + X
M = b + Y
small = 6 - X - Y - B
~~~

G是普通特饮数，M是主角特饮数，B为大音符包数，small为小音符包数。Y是扣除首店保底后的额外主饮，不等于M。给定Y后X与B独立；Y/B联合概率如下，不能将三者独立拼接。

| (Y,B) | (0,0) | (0,1) | (1,0) | (1,1) |
|---|---:|---:|---:|---:|
| 概率 | 1/15 | 5/15 | 2/15 | 7/15 |

Y边际为3/5，B边际为4/5。大／小音符可合并为8−G−M个非饮料占位；不能删掉占位后只在饮料中分折扣。每架独立生成本架随机量；X不复用Y或B的伯努利结果。

### 8.2 折扣生成

先在全部八件中均匀选择四件为折扣商品。第2、3家商店的**初始货架**使用 p_D=3/4；第1、4家商店初始货架以及全部商店的任何补货使用 p_D=7/10。五折件数：

\[
D=\min(2,\operatorname{Binomial}(3,p_D)).
\]

| 适用货架 | D=0 | D=1 | D=2 |
|---|---:|---:|---:|
| 第2、3家初始货架（p_D=3/4） | 1/64 | 9/64 | 54/64 |
| 第1、4家初始货架及全部补货（p_D=7/10） | 27/1000 | 189/1000 | 784/1000 |

D 独立抽取，不复用§8.1的饮料数量随机量 X。初始货架与补货由商店序号和当前操作区分。

在四件折扣商品中均匀选择 D 件五折，其余四件中的 4−D 件八折；非折扣四件原价。饮料原价200，实际价格为100、160、200之一。每个折扣子集的条件概率分别为 1/C(8,4) 和 1/C(4,D)。

生成完整货架后，边际化为 stock[普通／主角][100／160／200]。真实页面按类型、价格及商品 ID 排列，显示顺序不表示后台生成次序。

### 8.3 行动顺序

先 OPEN_SHOP 免费看到折扣，才选后续动作。候选行为：

- BUY：购买一种当前饮料，扣价、移除一瓶，进入对应 DRAW；完成潜能选择后返回原 SHOP。
- ENHANCE：扣当前机器费用并展示强化；确认后返回原 SHOP。
- RESTOCK：支付 100，restocks 减 1，整架替换；数量仍取 `b=int(shopOrdinal==1)`，折扣使用补货分布。
- LEAVE：结束当前商店，推进路线；最终一家结束后才 END。

可买后强化、强化后买、交替、多次补货；购买或强化生成的当前奖励必须先处理完，不能带着未选页面继续买下一瓶。

## 9. 战斗金币与追加 NPC

### 9.1 额外金币

每场战斗先加对应基础金币，再用：

\[
b_C(g,f)=
\begin{cases}
0&g=5\\
\min(30(f+1),100)/101&g<5
\end{cases}
\]

判断是否额外加 50。四档为 30/101、60/101、90/101、100/101，不是 30%、60%、90%、100%。

成功后 (g,f)→(g+1,0)；失败后 f 截到 3；达到五次成功后规范化 (5,0)。首战额外金币通过(gC,fC)更新其后金币过程；新版NPC核不再额外读取首战结果。

第 7 层照常结算。不同战斗的随机判断依赖计数；不可以把每场都写成独立固定 30%。

### 9.2 金币观察边界

自动推进到下一处实际界面时，才用可见金币更新 cBel。观察接口规定：

- 第 7、8 层之间没有一个可决策且单独记录金币的界面，观察到的是两场合计；
- 第 14 层若没有追加 NPC，会与第 15 层一起到下一个核心界面；
- 第 14 层若出现 NPC，则其事件界面提供中间金币观察；
- 核心虽不优化，仍保留为金币观察点。

因此相同合计金币可对应多个后台路径。例如两场中恰有一次 +50 时，不能自行认定发生在前一场或后一场。

### 9.3 追加 NPC 次数：统一战斗计数核

每场战斗令k=min(4,k+1)，包含第7层。只在第1、3、10、14、17层检查追加NPC，全部使用：

\[
P(\mathrm{extra\ NPC}\mid k)=\frac{\min(30k,100)}{101}.
\]

出现后k=0；未出现不归零。固定事件和商店不清零；关闭NPC之前，该次追加已经算作出现并清零。

在第3层，令A仅作解释性记号，表示第1层是否出现过追加NPC，则此时k=2−A，故：

\[
P(\mathrm{NPC}_3\mid A)=\frac{60-30A}{101}.
\]

| 第1层追加NPC | 第3层检查前k | 概率 |
|---|---:|---:|
| 未出现 | 2 | 60/101 |
| 已出现 | 1 | 30/101 |

A由k表示，不增加独立状态坐标；G1与npc3EventReward不参与状态和转移。

## 10. NPC 类型、全菜单与事件结果

### 10.1 选择事件类型

seen保存本局已出现的非121事件类型，包含105。非121事件出现即加入seen，选择结果或关闭动作不改变该记忆。121不加入seen，每次普通事件抽取都保留其权重。

普通事件类型为101～128除105，完整整数权重见§10.2，初始总和382。每次抽取的可用集合为：

```text
A = {e in ordinaryTypes : e not in seen or e == 121}
W = sum(weight[e] for e in A)
```

在floor<5且105不在seen时：

- 以2/3生成105；
- 其余1/3按普通池权重生成e，即P(e)=(1/3)×weight[e]/W。

其他时候，P(e)=weight[e]/W。105的普通池权重为0，第一家商店之后不再进入。121始终保留正权重，因此正常状态下W>0；输入权重或目录导致W=0时返回MODEL_GAP(EVENT_POOL_EMPTY)。

固定NPC与追加NPC共用seen和本节程序。eventId表示本规格的效果类型，由静态事件／选项映射或完整选项效果识别；不以NPC形象或对话文案单独确定类型。

NPC身份仅用于同一事件的文案映射，不影响动作收益、事件权重或seen，不作为状态坐标。商人NPC9133、药剂NPC9172、命运交易NPC9173、求助NPC9174共用EvtId=121；客户端按actionId=EvtId×10000+NPCId读取文案。121按事件ID处理，可重复且不加入seen；不维护NPC级已见集合，也不再将同NPC是否重复列作观察任务。

### 10.2 结果表的符号与执行约定

“常规潜能”指 regular 来源，稀有基础 1/5；“普通品质”指 common 来源；“稀有品质”指 rare 来源。都进入完整普通抽取链，不是直接给固定等级。

## 11. 观察合并与后验更新

记 x 为公开状态，z 为隐藏状态，b(z) 为后验。动作 a 的微观核给出 (x',z',o)。必须先计算：

\[
P(o\mid x,b,a)=\sum_{z,z'}b(z)P(x',z',o\mid x,z,a)
\]

\[
b_o(z')=
\frac{\sum_z b(z)P(x',z',o\mid x,z,a)}
     {P(o\mid x,b,a)}.
\]

相同 o 对应的 x' 必须相同，或能从 o 与已知历史唯一恢复。策略后继是 (x',b_o)，不是每条 z' 微观路径。

只用“当前 +2 概率”替代 eBel 不够：确定 (0,0)，与 3/10 在 (0,3) 加 7/10 在 (5,0)，当前成功率同为 3/10；观察下一次失败后，前者再下一次为 3/5，后者为 0。

## 13. 输入边界与确定返回值

### 13.1 选项可用性与随机结果更新

确定性消费采用“支付得起才可执行”。随机亏损不是预付价格，不按最大可能亏损额额外禁用选项，也不因此返回MODEL_GAP。

真实菜单中FailedIdxes指定的0基索引不可选择；其余选项正常执行给定分支。钱包按coins←coins＋Qty直接更新，不额外夹到零，也不补偿负收益。上述可用性与更新规则固定，不再列为观察或复核任务。对应实现为NpcOptionCtrl的禁用索引检查和StarTowerLevelData:ProcessChangeInfo的Qty累加。

### 13.2 库存、目录与来源边界

- 对选中角色，F为实际已满6级非核心种数。F≥10等价于新旧分配后的n超过未学总库存，返回MODEL_GAP(NEW_POOL_EXHAUSTED)；不生成该普通页。
- 任一品质分区需要的k超过该分区R+C：返回MODEL_GAP(PARTITION_POOL_EXHAUSTED)。
- 缺少合法潜能ID／品质目录、输入目录不适用本规格、缺少执行所需初序分布：分别返回对应CATALOGUE类MODEL_GAP。
- 奖励来源或事件选项不在输入映射中：返回MODEL_GAP(SOURCE_INPUT_MISSING)或MODEL_GAP(EVENT_INPUT_MISSING)。
- 事件权重输入产生空可用集合：返回MODEL_GAP(EVENT_POOL_EMPTY)。

上述检查在相应随机转移前执行，不自动改配额、不借用另一新旧分区。单一品质库存不足但该分区总库存够用时，直接执行§5.3的品质裁剪公式。新普通不足的精确条件为F_C−U_R≥7；该条件本身不触发MODEL_GAP，只有总库存不足等上述输入边界触发返回。

这两个库存等价式使用§1.1的每角色3稀有＋9普通目录与§5.2的q尾档。c低于尾档时普通新库存至少4、总新库存至少7，均不少于最多3个新项；进入尾档后n=max(0,3−u)。u≥3时n=0，不触发新库存不足；u≤2时，普通新库存减n、总新库存减n分别为6−F_C+U_R和9−F。

强化合法池M=0时没有ENHANCE动作；M>0时按min(3,M)生成强化候选。普通页不套用强化的减候选规则。

## 14. 版本与快照迁移

所有规则表、策略缓存和快照标记使用`state_space_v6_20261115_r4`。版本不一致时禁止直接载入并返回MODEL_VERSION_MISMATCH，进入明确的字段与后验迁移流程。可精确迁移的公开字段按映射复制，并保留来源版本与观察来源；它们不因版本不同而自动成为MODEL_GAP。
